# 0007: accounting permission model

## Status

Accepted

## Context

経理担当者は申請の最終承認や精算処理を行うため、一般社員や課長とは異なる
操作権限が必要である。

一方で、初期段階から複雑な role 管理や権限テーブルを導入すると、
ユーザー管理の設計範囲が大きくなる。

## Decision

初期の経理権限は部署判定で扱う。

ユーザーが経理部署に所属している場合に、経理としての操作を許可する。
経理権限専用の role 管理、権限付与 UI、個人単位の override は
初期実装では扱わない。

## Consequences

- 経理権限の判定を単純に保てる。
- ユーザーと部署の関係が権限判定の前提になる。
- 経理部署以外のユーザーに個別権限を付ける要件が出た場合は、
  別 issue と ADR で権限モデルを再検討する。
- 部署名や部署コードの正本をどこに置くかは、ユーザー管理の実装 issue で
  決定する。
