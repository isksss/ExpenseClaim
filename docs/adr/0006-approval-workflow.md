# 0006: approval workflow

## Status

Accepted

## Context

経費申請では、申請者、管理者、経理がそれぞれ異なる責務を持つ。
初期実装で承認経路を柔軟にしすぎると、設定画面やルールエンジンが必要になり、
業務フローの検証よりも基盤実装が先に膨らむ。

まずは扱う業務範囲を固定し、承認状態と操作権限を明確にする必要がある。

## Decision

初期の承認フローは固定承認フローとする。

申請は社員が作成し、課長が承認し、経理が最終承認する。
承認経路は「社員 -> 課長 -> 経理最終承認」に固定し、初期実装では
部署別の多段承認、代理承認、金額別承認、差し戻し先変更などの
動的ワークフローは扱わない。

## Consequences

- 状態遷移と権限判定を単純に保てる。
- 初期リリースで検証すべき業務フローが明確になる。
- 動的な承認ルールが必要になった場合は、別 issue と ADR で再検討する。
- 固定フローを前提にした UI と API になるため、将来拡張時には
  migration と互換性確認が必要になる。
